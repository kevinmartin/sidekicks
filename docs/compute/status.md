# Compute layer status

This work is in progress and has not been accepted as production ready. The historical POC baseline and verification evidence described below are **external workstation-local evidence**: the `reference/poc` branch, `poc-baseline-2026-10-30` tag, ignored artifacts, VM disks and local images are not guaranteed to exist in a fresh clone or on the remote. They are not an off-host backup and cannot independently substantiate these historical claims for a remote reader.

The then-uncommitted source was built into four separate, unpromoted candidate images and tested on 2026-10-30. Shell and Chromium integration passed; both desktop viewers passed real local end-to-end tests, including input, restart and cleanup (14 noVNC checks and 15 Neko checks, including synthetic audio). Isolated Browser, Terminal and Files lifecycle tests passed on one-layer test derivatives of the rebuilt desktops. All 48 protected Docker containers and eight existing image tags matched their pre-build state afterward. The exact candidate IDs, source fingerprint and logs are in `artifacts/compute/candidate-build/44be00ed03d0ca480622b19dc4fe0228/` and `artifacts/compute/image-remediation/clean-candidate-verification/`. The source fingerprint predates subsequent documentation-only commits. At that revision, a complete `make verify` had not been recorded; the then-current target built and retagged existing `:clean` and `:dev` images. The current target builds uniquely tagged candidates without replacing those tags and binds the subsequent checks to their immutable IDs. The earlier `make check` passed with 84.69% overall statement coverage and the configured package floors; its loopback-based tests required access outside the restricted sandbox. The log is `artifacts/compute/image-remediation/clean-candidate-verification/final-make-check-elevated.log`.

The release scan of those exact four images completed but its security gate failed: it reported 43, 63, 99 and 228 high/critical package-image occurrences for shell, Chromium, noVNC and Neko respectively. These counts may include repeated advisory IDs and do not establish exploitability. Go source and npm scans reported no findings. See `artifacts/compute/release/20261030T124323.982773000Z/` for the scan, database identity and limitations. A separate Neko image without GStreamer Bad reduced a prior scan from 107 to 78 distinct high/critical IDs, but removes optional upstream codec and broadcast capabilities beyond the tested VP8/Opus path; it is not promoted. Earlier focus and cleanup failures remain recorded. No candidate has been promoted. See [security boundaries](security.md) for release limits.

Four workload IDs are registered: `shell`, `browser-chromium`, `desktop-novnc`, and `desktop-neko`. Workloads and isolation runtimes have separate interfaces. Docker on a local Unix socket is the implemented runtime. Apple Virtualization.framework and Kubernetes are explicitly unsupported by this new layer; historical VM POCs are preserved and are not evidence of a completed generic backend. Profiles, agent loops and a new harness are deferred. Headless shell and browser services have no desktop dependency.

Docker creates labelled owned containers with non-root UID, read-only root, dropped capabilities, no-new-privileges, resource caps, bounded tmpfs, and no host mounts or Docker socket. Network defaults to none. An explicit egress choice allows loopback-published desktop viewer ports; this is not egress isolation. The private guest agent is reached over fixed Docker exec transport and uses authenticated loopback HTTP within the guest. Published viewers use one-time tickets, same-origin controls and lease generation fencing. These are local compute services, not an authentication solution for hostile networks.

The command service captures output with bounds while it runs, and cancellation kills its process group. A deliberately daemonizing guest process can escape that process group; destroying the container remains the ultimate cleanup boundary. Previously delivered application events cannot be recalled. Actual Linux X11 release and browser/video behavior require the real-guest tests, not only unit tests. Native physical key mapping and mobile devices are not established by headless tests.

Shell and headless Chromium passed disposable Docker integration on this Mac with networking disabled, including guest exec/files, lifecycle, CDP navigation/DOM and PNG decoding. A running shell command was canceled through Docker after its start was observed; the guest acknowledged cancellation and its delayed file write did not occur. Separately, real X11 guest tests exercised held-input reset, capture and the browser/terminal/files launch, restore, close and reopen paths. The real-app test ran Chromium without deliberately disabling its sandbox. A later source-matched real X11 test verified that normalized `+` preserves a pre-held Shift. These checks do not establish behavior for deliberately detached processes or other hosts.

On the earlier committed baseline `618dc7c`, the noVNC and Neko E2E runs recorded 14 and 13 functional checks respectively. Both exercised decoded desktop frames, actual agent Shift input, human takeover and observed held-input release, real viewer typing/clicking, and a normal stop/start followed by fresh input and capture. Neko selected an allocated loopback UDP ICE pair and decoded VP8 frames. The coordinator inspected the saved decoded Home images. These are synthetic local browser tests, not physical keyboard, mobile, WAN or performance evidence. Earlier failures remain in `artifacts/compute/e2e/`.

**The complete `make verify` on baseline `618dc7c` passed** on 2026-10-30 after the user authorized a separate task to stop the unused n8n stack. Both viewer runs passed the strict before/after audit of every existing Docker container, including stopped containers and other compute instances. Earlier runs remain recorded as failures: their audit observed `pickleballworkflows-n8n-worker-1` restarting during the tests. The test commands targeted only generated compute containers, but that audit could not establish why the worker restarted. Read-only Docker events showed it continuing to restart after those tests ended; this does not prove the absence of indirect effects. The later passing run does not rewrite those earlier results. Existing POC containers were not deliberately replaced by these tests.

`make check` verifies formatting, static analysis, race tests, coverage floors and Linux cross-compilation. In that baseline `make verify`, it passed with **85.10% overall statement coverage** and all configured critical-package floors; Linux ARM64 and AMD64 compilation passed. The release verifier has a separate coverage gate, which passed at 88.72%. The same run built all four clean images and passed the shell/Chromium Docker integration and desktop E2E. The log is `artifacts/compute/verify-stable-baseline.log`; individual E2E artifacts are retained separately. On 2026-10-30, the Go advisory scan reported no reachable vulnerabilities in this module and npm audit reported no advisories in the locked web dependency graph. These two results do not scan Debian packages, browser binaries, or Neko's separately built Go dependency graph, and do not establish an absence of vulnerabilities.

Raw RFB input and Neko native/controller-WebSocket input are disabled in the new compute layer. Both viewers send supported keyboard and pointer input through the synchronized, lease-gated Go X11 driver. Native Neko input, IME/dead keys, non-US keyboard layouts and host clipboard transfer are not supported by that path. An uncertain interrupted X11 operation makes the guest unready until restart rather than promising a reset across a new connection. Cancellation acknowledgments confirm request completion or prevention of a future start, not rollback of completed side effects or an application event-queue flush. See the [Neko safety decision](../../internal/compute/neko/UPSTREAM-SAFETY.md).

Image builds use official pinned base image digests and verified upstream source archives. Debian package repositories are not snapshot-pinned, so the recipe is not yet a byte-for-byte reproducible release. No image signing, registry publication, production deployment, independent security audit or SLA has been completed. No performance benchmark has been run as part of this change.

An initial image advisory scan on 2026-10-30 found 125 distinct high/critical IDs across four exact image IDs. After updating the pinned Neko toolchain and dependency overlay, the final scan found 107 distinct high/critical IDs, all Debian/native package matches without a fixed version listed in that database snapshot; six are critical-rated IDs. The release policy therefore fails. Scanner severities and package-version matches do not establish runtime exploitability. The final Neko binary matched the SHA256 of the separately analyzed binary whose `govulncheck` analysis identified no vulnerable package or symbol findings; one module-only OpenPGP advisory remains with no affected package or symbol identified. These results do not establish exploit absence. Initial and final scans, image IDs and database hashes are preserved under `artifacts/compute/release/20261030T041013.048273000Z/` and `artifacts/compute/release/20261030T043830.142841000Z/`; binary evidence is under `artifacts/compute/neko-security/`. The upstream DTLS source suite retained a Go 1.27 certificate-fixture failure, and the full CGO source suite was not run on the Mac because the GStreamer development headers were absent.

The [security boundary and remaining release requirements](security.md) distinguish trusted host/Engine access from guest code, and describe the limits of the container, viewer and workspace controls.

On this existing workstation, a bare `go mod tidy` also discovers ignored historical Neko source snapshots under `pocs/microvm/neko-source/artifacts/`; those files are intentionally preserved and are not part of the new compute module's package checks. The attempted tidy did not complete. `make check` explicitly targets the new module packages. A clean checkout does not contain those ignored local snapshots; do not delete or edit the workstation evidence merely to make a broad package walk pass.
