# Desktop control

The desktop workloads share a Go-managed X11/Xfce session and fixed Browser, Terminal and Files launchers. `desktop-novnc` streams receive-only RFB through noVNC; `desktop-neko` streams WebRTC media through Neko. Human and agent input use the same lease-gated Go X11 driver, with ownership epochs and release of observed held keys and buttons on takeover or disconnect. Raw receive transports are not authorized input paths.

The guest agent exposes desktop control through its private authenticated interface. The local viewer uses a short-lived ticket and origin checks; it is designed for a trusted local host, not Internet exposure. Input cutoff prevents future accepted operations from the previous owner; it cannot retract input already delivered to an application's queue. See [security boundaries](../compute/security.md).

The desktop's window manager, file manager, browsers and stream encoders are upstream components. Their actual behavior requires real guest and viewer tests. Current source waits for the requested X11 window ID to be observed active and viewable before acknowledging restore; the observations are not atomic, do not prove the request caused focus or that the XID has not been reused, and a delivered request cannot be retracted after cancellation. Isolated app tests passed against test-only derivatives after waiting for a reopened browser to settle, while earlier focus failures remain recorded. Fresh unpromoted candidate images containing that source passed local viewer and isolated app tests; the image security release gate remains failed. Physical keyboard, mobile, WAN and performance behavior are outside the current evidence.
