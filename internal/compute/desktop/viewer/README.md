# Public desktop-only viewer service

`Service` serves one workload's browser viewer, not a machine API. It has no exec, filesystem, process, Docker or host-shell route. Private agent authentication is handled separately. `NewTicket` is invoked only by an already-authenticated private machine endpoint.

A one-use 32-byte random bootstrap ticket expires after one minute. Deliver it to the human as a URL fragment; the frontend consumes it with `POST /auth` and removes the fragment. The service stores only the ticket hash. Successful authentication sets a host-only, HttpOnly, SameSite=Strict cookie with a 30-minute lifetime. Cookie names are unique per service because browser cookies are not scoped by port. There are at most eight pending tickets and eight authenticated sessions. Rotating the same service's cookie retires only the old session and releases only its own still-current human lease.

The listener must be published on loopback. Requests require a numeric `127.0.0.1:port` Host, and unsafe methods and WebSocket upgrades require the exact `http://Host` Origin. No wildcard Host/Origin patterns or forwarded-header trust are used. Built-in JSON route bodies are limited to 64 KiB with strict fields and one JSON value; extension handlers are responsible for their own validation and limits. Asset routes are explicitly restricted; machine paths remain absent even when a desktop SDK extension is installed. These checks do not turn guest UI curation into a security sandbox.

Routes:

- `POST /auth {ticket}` consumes a bootstrap ticket and establishes the cookie.
- `GET /state` or `GET /control` returns sanitized ownership, this viewer's ownership flag, dimensions and a non-secret `epoch` generation (zero when not owned). Actual lease tokens are never returned to the browser.
- `POST /control {action, mode?, leaseMs?}` accepts acquire, renew, release or stop. The server always chooses owner=human and its own session identity. Native mode requires a server-observed native viewer resolver. Stop/release cannot globally revoke a foreign human or private agent. Renew/release/stop require the exact current generation in a single canonical positive decimal `X-Sidekicks-Epoch` header; acquisition is a new intent and is exempt.
- `POST /input {events}` first requires the current `X-Sidekicks-Epoch` and snapshots its exact private credentials, before reading/validating the batch, then gates each final driver dispatch as human/gated. Invalid batches release only this cookie's own currently gated human lease so a rejected batch cannot leave earlier input held. Foreign and native leases are preserved. Missing/malformed/stale epochs return 409 without parsing input or releasing a current owner. A request whose body completes after reacquisition cannot adopt the server's newer credentials, even on the same browser cookie.
- `GET /screenshot` permits authenticated read-only capture, bounded to one concurrent request, five seconds and 16 MiB.
- `GET /websockify` connects one fixed private RFB target for read-only video/negotiation. Raw RFB key/pointer/clipboard/resize/power input is rejected for every lease, including current humans; browser interaction uses the epoch- and lease-gated direct X11 `/input` route. There is at most one connection per cookie, and acquiring control does not require reconnecting the video stream. The server binds acquisitions to the exact stream and releases only its still-current lease on disconnect; the frontend also attempts to release its current epoch. A stream slot remains reserved until bounded disconnect cleanup completes. An acquisition racing a stream attachment or disconnection can return 409 and must be retried after the replacement stream connects. Repeated acquisition of the same lease retains the epoch and existing stream.

The noVNC frontend waits for a connected video stream before taking control. Blur, pagehide, stream disconnect, Release and viewer fullscreen actions invalidate an in-flight Take; a delayed successful acquisition is released using its exact epoch. A new Take waits for outstanding background releases so that an old release cannot revoke a reused epoch. An unconfirmed release closes the affected stream when appropriate, blocks further Take requests in that page and asks the user to reload; it is not treated as a successful cleanup.

Backend-specific extension hooks run only after cookie and authority checks. `ReadOnlyAdditionalPaths` may allow absent Origin on exact authenticated GET metadata paths, since same-origin browser fetch GET requests normally omit Origin. It does not relax WebSocket or unsafe-method Origin checks. Extensions must handle only their fixed desktop SDK routes and must not delegate a broad private API. RFB and SDK upgrades share one socket slot per cookie. Every authenticated request is linked to that cookie's lifecycle: rotation, expiry and service close cancel SDK streams as well as RFB streams. A scoped hijacked-connection wrapper also closes the owned TCP socket on cancellation independently of delayed backend cleanup. Backend disconnect callbacks must still use exact issued credentials so a late callback cannot revoke a replacement owner.

`OpaqueTicketQueryPaths` is a deliberately narrow Neko SDK compatibility exception: a configured exact `/desktop/stream/...` WebSocket path may carry one 43-character base64url token encoding 32 random bytes. Cookie and exact Origin remain mandatory, and the Neko extension must independently bind that opaque SDK token to the same authenticated session. It is not a backend password or a control lease token. Other ticket/token/session/auth query credentials remain rejected, and noVNC config has no exception by default.

`Config.OnAcquire` binds the exact newly acquired or renewed lease to backend viewer lifecycle records before the service stores credentials or acknowledges control. A binding error or panic releases only that exact lease using a bounded independent cleanup context. The service revalidates after binding, so a disconnect during host transfer/binding cannot retain or acknowledge an already revoked lease. Renewals bind the same generation/token. Cleanup cannot release a newer replacement owner. Hooks must be short local operations and must reject missing/disconnected backend reservations.

A backend input override must preserve final-dispatch ownership checks at its actual queued/native transport boundary; an earlier HTTP check is insufficient. Native Neko control also requires backend host transfer and revocation. The service's generic hooks alone do not establish that those backend mechanisms work.

Tests cover bootstrap replay/expiry/capacity, cookie isolation across ports, Host/Origin/private-route boundaries, strict input, own versus foreign release, native mode restrictions, extension allowlists, bounded capture, and actual loopback WebSocket cookie/lease binding and mutation rejection even for a current human; observer-first Take and abrupt disconnect; repeated-Take stream continuity; disconnect during an in-flight acquisition and replacement-stream fencing; epoch-bound delayed requests; and SDK socket close on rotation/expiry/shutdown with late-old-callback owner preservation. Physical browser/device behavior and real guest backend checks remain separate integration evidence.
