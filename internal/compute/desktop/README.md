# Desktop protocol boundary

This package is the Go port of Sidekicks-owned protocol enforcement. Upstream noVNC remains the browser RFB client. Existing POC containers and their Python/Node services are preserved independently; this package does not replace a running POC.

`ClientFrames` recognizes the deliberately narrow historical RFB 3.8 / None / shared-desktop client stream. It frames fragmented/coalesced client messages before distinguishing read-only framebuffer/encoding/fence requests from mutating key, pointer, clipboard, desktop-resize and power events. Individual messages and buffered fragments are bounded to 1 MiB. Invalid messages poison the connection; no messages from a failing parser call are returned.

`Gateway` exposes one fixed numeric-loopback upstream through binary WebSocket messages. It requires an exact Host list, exact Origin list and an authentication function before upgrading or dialing. The HTTP path is fixed, query credentials are rejected, WebSocket compression is disabled, text frames are rejected, and a bounded connection pool limits simultaneous viewer buffers (eight by default, configurable from one to 32). It does not expose control acquisition, shell execution, arbitrary upstream targets or host networking. A reverse proxy must preserve the authenticated viewer identity and enforce its own listener policy; this handler does not make a wildcard unauthenticated listener safe.

`Bridge` is permanently read-only for RFB input. Every key, pointer, clipboard, resize and power frame is rejected before any upstream write, including with a valid current human lease. Handshake, encoding/framebuffer/fence requests and server-to-client video remain available. A mutating frame closes that viewer's connection. The raw x11vnc process also starts with its supported `-viewonly` flag as defense in depth. Direct synchronized Go X11 dispatch is the sole supported new-compute input path: checking an RFB lease before a TCP write cannot fence a separately queued x11vnc injection. Canceling a blocked read-only write closes that connection promptly. Disconnect still releases only that connection's own current gated human lease so direct input does not remain held; it cannot release a foreign or native lease.

The injected control driver must release actual input state, including input held through another accepted route, before acknowledging reset. Tracking only viewer bookkeeping is insufficient for mixed RFB/API input. A successful cutoff stops future injection; it does not flush application queues or undo previously injected input.

This RFB package does **not** implement Neko native signaling/control-host transfer. Neko's browser data channel bypasses a normalized HTTP input endpoint, so an HTTP lease check alone would not enforce native ownership. The separate Neko integration must establish host transfer/revocation and decoded/input tests at that boundary; generic viewer hooks alone do not establish support. The existing independently tested Neko POC remains available as reference behavior.

Unit tests cover parser bounds/classification/poisoning, fragmented/coalesced messages, agent/stale-owner rejection, disconnect release/reset failure, HTTP Host/Origin/auth/path boundaries and real loopback WebSocket transport. RFB fuzz seeds run with ordinary `go test`; extended fuzz campaigns and real desktop frame/input acceptance are separate checks, not implied by parser coverage.

## Guest X11 driver

`x11.Open` connects only a numeric guest-local Unix display. It uses pure-Go XGB and XTEST; no Python, xdotool subprocess, cgo, host display, remote X11 connection or host shell is involved. `Reset` reads the server's actual key map and pointer mask, releases every pressed keycode and all supported pointer buttons 1–8, then re-queries held state. Releasing buttons 6–8 is deliberate because the core X11 pointer mask exposes only buttons 1–5. The control manager must finish reset before acknowledging takeover.

Normalized `Event` batches are syntactically validated before dispatch; dispatch each event under `control.Manager.DispatchGated`. Text is currently limited to printable ASCII, LF and Tab with the guest's fixed keyboard mapping. Exact case uses observed keymap Shift levels; Caps Lock text is rejected rather than silently producing the wrong case. Physical punctuation accepts the unshifted semicolon, equals, backtick, brackets, backslash, slash, comma, period and apostrophe; Shift is held separately. The existing space/minus/plus contract remains available. General Unicode/IME/layout switching remains unsupported. These are capability limitations, not a reason to bypass the lease gate. Raw upstream noVNC typing remains separate from normalized text.

Cancellation closes the active X11 connection to interrupt blocking I/O. If an operation is canceled or fails before checked completion, its input-consumption ordering is uncertain: this driver remains unready, reset cannot acknowledge success through a different connection, and new ownership is refused until the guest/container lifecycle is restarted. This conservative rule also applies to unclassified read-only X11 I/O failures. Both private desktop health and public state expose the unavailable driver even before a gate dispatch. Normal checked X11 operations and resets retain their actual-server acknowledgments; no generic application-queue flush is promised. Driver shutdown still bounds reset and closes a stuck backend outside the I/O lock. Paused-backend regressions prove uncertain old input cannot cause a new lease acknowledgment, and shutdown still unblocks owned I/O. The control manager should close before the driver.

Capture uses fresh root-window `GetImage` data, validates pixel format/masks/dimensions and encodes PNG in Go. Captures are limited to 4,194,304 pixels and 16 MiB encoded output. It supports TrueColor 16/24/32-bit formats with documented scanline padding and byte order. The native hardware cursor is not composited into the PNG.

`TestRealGuestX11` is opt-in through `SIDEKICKS_X11_TEST_DISPLAY` and requires UID 1000. It creates only a synthetic override-redirect test window inside a disposable guest, independently holds a key and button, verifies actual release, checks exact-case/punctuation key events and compares four known-color pixels in a fresh PNG. Default unit runs skip that test; fake-backend coverage is reported separately from any real guest invocation. Do not run it against a user's active desktop.
