# Canonical Xfce staging configuration

Owner: noVNC worker, by integration delegation. Integration owns the parent GTK3 CSS/settings/icons/Xresources. Other backend workers copy this directory read-only into their own contexts and render it at image build time. No proprietary cloud reference assets are included.

This is provisional while actual noVNC4.18 and Neko4.20 staging verification runs; it is not live-production acceptance. Current4.18 stage starts a standard xfce4-session under its own session D-Bus and has exactly one xfwm4, xfsettingsd, xfce4-panel, xfdesktop and Thunar daemon, with no Openbox/tint2/picom. Installed Debian failsafe session owns those five components at priorities15/20/25/30/35. The backend must export the same session D-Bus to its adapter-launched GUI processes.

Run `generate.py` with `--output`, `--home`, `--browser-command`, `--terminal-command`, `--files-command`, `--wallpaper` and `--icons`. Commands are backend-owned fixed command strings. No command is executed by the generator. Install `output/user/` into the guest home, and `output/system/` under `/etc/xdg/`, then set user ownership only on the former. Install the parent GTK3 settings/CSS/icon overlay and merge its Xresources separately. Do not run a generated config installer against Kevin's active comparison desktop.

Pass the actual XRandR output through `--monitor` (default `screen` for noVNC Xvfb; observed `DUMMY0` for Neko Xorg). Wallpaper keys are generated for that output and the legacy monitor0 fallback. The generator also emits per-user Hidden=true XDG autostart overrides for picom/tint2/Openbox and the duplicate xfsettingsd desktop entry. The normal failsafe session still owns xfsettingsd; these stubs prevent old-stack/duplicate attempts, not the intended session component.

noVNC substitutions: home `/home/desktop`, commands `python3 /app/desktop-app.py browser|terminal|files`, wallpaper `/app/desktop-assets/wallpaper.png`, icons `/app/desktop-assets/icons`.

Neko substitutions: home `/home/neko`, commands `/etc/sidekicks/browser.sh`, `/etc/sidekicks/terminal.sh`, `/etc/sidekicks/files.sh`, wallpaper `/etc/sidekicks/wallpaper.png`, icons directory containing the backend's browser/terminal/files PNGs. Browser Home URL belongs to the backend launcher/profile, not these visual templates; noVNC uses8080/home, Neko7792/home.

Readiness criteria: actual `xfwm4`, `xfsettingsd`, `xfce4-panel`, `xfdesktop`, `xfce4-session` processes, plus a mapped normal managed Browser. In4.18 the actual panel title is `xfce4-panel`, WM_CLASS includes `Xfce4-panel`, and `_NET_WM_WINDOW_TYPE_DOCK` is set. Do not filter the panel as a normal application. The panel has three launcher plugins, each invoking the same fixed helper as Home/hotkeys and preserving same-window restore through that helper.

Shortcuts: Super+B Browser, Super+Return Terminal, Super+E Files, Super+D desktop; Alt+F4 close, Alt+F9 minimize, Alt+F10 maximize/restore, Alt+Tab next, Alt+Shift+Tab previous, Alt+F12 window fullscreen. Browser F11 is independent. Alt+F7/F8 and Escape/arrows retain keyboard move/resize. The custom commands list omits logout/restart and broken optional software shortcuts. Xfwm action names were read from the installed4.18 official defaults.

Primary terminal is GTK3/VTE, DejaVu Sans Mono11, navy10263d/e8f7ff, cyan cursor, geometry88x24. Newer Neko terminal supports `--disable-server --class=SidekicksTerminal`; Debian bookworm terminal1.0.4 rejects `--class`, so noVNC uses `--disable-server --role=SidekicksTerminal`, actual WM_CLASS Xfce4-terminal, and accepts only that class plus exact role in its helper. Pass `--terminal-wm-class Xfce4-terminal` to generate accurate desktop metadata for that version. Do not claim the literal class is identical across those versions. Keep XTerm/UXTerm shared resources for legacy compatibility. Neko4.20 reported successful one-time terminalrc→Xfconf migration with all configured values preserved; the migration message alone is not a defect.

Menus are UX curation, not a security sandbox. Panel system channel uses `unlocked="root"`, following the documented named-user allowlist; the first `locked="*"` incorrectly named a nonexistent user and did not lock anything. Actual menu checks on4.18/4.20 confirm customization is removed by this correction. Stock Help/About/Log Out are appended unconditionally upstream and remain; their actual behavior must be recorded by each backend. Parent explicitly selected supported lock behavior over custom interception. The failed passive guard was removed from future source/autostart/readiness, and its BadAccess/zero-eligible-descendant evidence is preserved by noVNC. No descendant/global grabs, overlays, GTK modules or panel patches are shipped.

The locked panel property format, keyboard custom override, compositor, monitor wallpaper keys and desktop-menu behavior need4.20 observation. Report differences before making independent visual variants. The current files use stable4.18 properties and avoid unsupported new4.20-only properties.
